Pending integrator verification. Use a production build on the normal app origin, with DevTools Network and Application panels available. These steps were not run in a browser in the socket-restricted worktree. Supplemental socket-free VM and real-dispatch checks: `node --test client/c1.test.mjs` (uses installed esbuild, no added dependencies).

- [ ] **C13 / M16 — Single submission:** Enable Slow 3G; rapidly double-click or press Enter twice for lesson final answer, Money Save/Spent/Cash diary/Ask for extra, Send bear, mission Done, budget Finish, trade Propose, friend Send, greet, cosmetic Buy/Equip/None, Rename, Buddy Send/read aloud, PIN Unlock, and Parent Approve/Decline/Mark handled/Create goal/Assign task/Save rules/Update savings goal/Topup/Run-now/Inject-fault/Reset/settings toggles; all POST controls in that view disable until settlement, only one action request is sent, and errors re-enable controls.
- [ ] **C12 — Stable sheet focus:** Open My money, focus the amount or memo, type through at least two five-second polls and an SSE update; focus and the mobile keyboard remain in the field; Escape still closes using the latest callback. Review Child/Parent effects: none depend on an inline callback prop.
- [ ] **S6 / B5b — Parent lock:** On a parent session with a PIN, unlock, use Kid mode, then Grown-ups: the PIN sheet is required again. Repeat with the app-bar Lock button. Cancel returns to kid mode. Without a PIN, Grown-ups returns directly and suggests setting a PIN in Security. The session stays cookie-backed; this is a local UI lock, not server-side revocation of the existing unlock window.
- [ ] **C6 / B5b — Immediate unauthorized handling:** Revoke/expire a session and click an action before the next poll: an authenticated-route 401 clears cached state/identity and returns to Welcome immediately. Wrong-password auth/login and wrong-PIN parent/unlock 401 responses stay inline, preserve inputs and keep cached identity; Welcome demo discovery also handles its expected 401 locally. A parent action returning 423, or 403 with “Please unlock parent mode”, opens the PIN sheet; a child-access 403 must not grant or reveal parent UI. A 429 shows the server message in a toast and reaches the form’s inline error handler. Restart alone does not revoke a persisted session.
- [ ] **C9 — Repeated saves:** In My money choose $1 or $2 and save three times after each prior response; the amount stays in the field, the sheet stays open, and exactly three transfers occur. For Spend, verify the successful request does not clear the amount before the sheet closes.
- [ ] **C5 — Weekly budget state:** Finish a valid budget; after refresh Missions shows a checked, disabled Weekly budget challenge with no +50; reload preserves it. With an earlier server week in `lastBudgetWeek`, it becomes available again; do not derive this from the browser timezone.
- [ ] **Lesson replay copy:** Complete an already-passed lesson with a result containing `firstTime: false`; see “Nice review! No extra points for repeats.” without +20. Fail a final-answer request once, retry that answer, and verify the payload still has exactly one answer per question.
- [ ] **C4 — Parent form refresh:** Keep Goals or Allowance open in one parent tab and change the corresponding server values from a second authorized tab; after refresh the first form shows the new title/target or allowance/rules. Ordinary polls and next-payday changes must preserve typed values; a conflicting change to editable server values intentionally remounts only that form. A savings-goal edit must preserve the unsaved reward-goal/task drafts; unrelated security settings must preserve the allowance draft.
- [ ] **C7 — Empty savings goals:** Intercept the state responses to return `goals: []`; Child Home/Buddy and Parent Overview/Goals render “Set a savings goal” without errors. Home still opens My money, Buddy offers a goal suggestion, and Parent Goals shows blank title/default target fields.
- [ ] **C16 (also C15) — Navigation, reveal, connection copy:** Set `localStorage.mq_tab` to an unknown name and reload: Home renders. Leave a money/lesson sheet open until a trip returns: only the return reveal remains, and dismissing it never reopens the old sheet. At PIN, URL retains `?role=parent`; reload rechecks the cookie session, preserves local Kid mode/Lock, and checks the server unlock deadline. Fail refresh: a loaded child/parent header shows Offline; a first visit without cached state shows “Can't reach MoneyQuest right now. Check your connection and try again.” with no port number, a Try again button that reloads state, and (for a parent in Kid mode) Back to grown-ups through the normal PIN gate. Child sessions must never show that parent control.
- [ ] **C1 / C14 / C2 / C3 / C11 — Service worker and offline:** Clear site data, visit the production app once, wait for SW activation/art warming, then inspect cache `mq-v5` for `/`, every built hashed JS/CSS reference, manifest and all icons; registration starts without waiting for window load. Open Album offline (including a collected postcard not opened online), reload offline and inspect Home: a paired child session with matching cached identity and JSON in `mq_last_state` renders, art is available, Offline pill/toast appears, and every mutation/voice request is disabled with zero POSTs. Reconnect: fresh state replaces the snapshot and actions re-enable. Return a 503 navigation or 404 static asset online: neither overwrites the good cache; offline navigation still opens the app. Consume a successful navigation response: cache write has no body-used error. `/api/*` never enters Cache Storage. Update the SW: controllerchange shows a persistent, clickable “Updated! Tap to reload” toast; tapping reloads.
- [ ] **C8 — Keyboard and label access:** Open a sheet from a focused button, Tab through all controls and Shift+Tab backwards: focus wraps inside; Escape/Close restores the opener. Focus a normal and secret map pin, press Space and Enter: each opens its sheet once and Space does not scroll the page. Clicking “How much?” focuses `#money-amount`; its label contains no div.
- [ ] **Map (AG2 #1) — Respect map interaction:** On a narrow screen start a trip and observe the walking bear near an edge; automatic horizontal scroll starts at most once per two seconds. Touch/hold, drag, mouse-drag or trackpad-scroll the map: it stays under user control, resuming only after release plus two quiet seconds; normal pin clicks still work.


## B5b accounts, pairing and child selection

These browser steps remain pending; the socket-free VM tests cover handlers, request fields and routing, not browser cookie enforcement or a second real profile.

- [ ] **Create family:** With no cookie, Welcome offers Sign in / Create family / I have a kid code. Create a family on one screen using name, email, an 8+ character password, child name, age 7–12 and bear name. Inspect the register body for the browser's IANA timezone. The HttpOnly session cookie is set and the parent app appears; no session token is returned or stored by the client.
- [ ] **Sign in:** Sign out, sign in with email/password, and reload. With a configured PIN, password login opens the PIN sheet; without one it opens the parent app. Invalid credentials stay on Sign in, preserve the email/password and show the server error inline. Rate-limit errors show the server's friendly copy inline and in a toast; retry works after the limit expires.
- [ ] **Children / code:** Open Children, add a second child, and verify the list and app-bar switcher update. Generate a code for either child, including the child that is not selected. Inspect path ID and `?child=`: they must match the pairing target. Confirm a six-character, selectable/copyable code and countdown from 15:00; expiry disables copying and asks for a new code. On HTTPS, Copy code copies the displayed code; without clipboard access, select/copy the read-only field.
- [ ] **Second browser profile:** In a separate profile/device, choose I have a kid code. Use typing/paste or the large code keys and Delete; only BCDFGHJKMNPQRTVWXY346789 survive input filtering (lowercase becomes uppercase; vowels, ambiguous characters, punctuation and spaces are removed before the six-character cap). Submit the code. The kid app opens for the bound child, with no Grown-ups button, parent navigation or parent forms. A used/expired code fails with server copy. Refresh retains the paired child session.
- [ ] **Switch children:** Switch between two children in the parent app. Verify balances, allowance, approvals, chat and forms all switch without flashing the previous child's state. Inspect state, POST, SSE and voice calls for the selected `?child=`. Sibling SSE events must not refresh the currently displayed child. Reload preserves a valid selected child; another family's stale stored selection falls back to a child in the current Me response.
- [ ] **404 child recovery:** Select a child that becomes unavailable; force a 404 on state, parent/state or another selected-child request. The client fetches auth/me without the stale child query, selects/persists the first current child and remounts its state view. Repeat in Kid mode: it stays in Kid mode and loads the first child without needing the hidden switcher. A delayed old-child 404 or recovery response must not override a newer selection or sign-out. A 404 without a child query must not reset the selection.
- [ ] **Security / PIN:** Set a 4–8 digit PIN, then change it while unlocked. Enter Kid mode and return via Grown-ups to unlock. Verify no default/demo PIN is advertised. Let the server unlock window expire and trigger a parent action: documented locked 403 (or 423) opens PIN. Wrong PIN stays on the sheet with attempts left and preserves the PIN/session. Successful unlock resets the count. The fifth failure returns 429: the sheet says “Locked for 15 minutes — try again at …” in en-US time and disables Unlock. Retry after the full lockout expires.
- [ ] **Sign out:** Use app-bar or Security Sign out on a parent device. Paired child devices have no Sign out control; unlink them from Parent → Children → Devices. The logout POST clears the cookie and Welcome replaces the app; cached child identity/state is removed. Reload offline after explicit logout must not reopen that child's state. A failed network logout must not claim success. Current Sign out revokes only this session.
- [ ] **Sign out everywhere:** In Security, click Sign out everywhere: a confirmation explains that all family sessions will end, including kid devices and this device; new kid codes will be needed. Cancel sends no POST. Confirm sends cookie-backed POST auth/logout-all, disables repeat submissions, clears local identity/state and returns to Welcome only on success. Network/500 failures keep the session visible. An expired PIN unlock (403 locked or 423) opens the PIN sheet; unlock and confirm again. Verify all parents and kids in this family get 401 afterwards; other families remain signed in.
- [ ] **Demo availability:** With MQ_DEMO on and off, open Welcome without a cookie: GET auth/me returns 401 `{error,demo}`, and Try the demo family appears only for `demo: true`. Authenticated Me is true only for the demo family; real families receive false even on a demo-enabled server. Welcome fetches availability again after logout and after returning from Sign in; a later `false` hides a previously shown button. A slow discovery response must not interrupt a subsequently opened Sign in form. The demo button posts to demo/login; no automatic demo sign-in.
- [ ] **Buddy chats:** With a non-null `chatNextBefore`, Load older sends `?before=<cursor>` together with the selected child, prepends messages once, and stops when the next cursor is null. Current server returns up to all 200 retained messages on the first page, so Load older normally will not appear; pruned messages cannot be retrieved.
- [ ] **Child offline recovery:** Pair a child, allow state/art to cache, go offline and reload: only that child's cached app appears with mutations and voice disabled. Parent sessions and mismatched/missing child snapshots do not restore an offline parent view. Reconnect and verify fresh child state replaces the snapshot. Force a 401: Welcome appears without falling back to cached identity. Delay an old child's response, switch children or sign out, then release it: it must not repopulate the snapshot.
