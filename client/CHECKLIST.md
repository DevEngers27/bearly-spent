Pending integrator verification. Use a production build on the normal app origin, with DevTools Network and Application panels available. These steps were not run in a browser in the socket-restricted worktree. Supplemental socket-free checks: `node --test client/c1.test.mjs` (uses installed esbuild, no added dependencies).

- [ ] **C13 / M16 — Single submission:** Enable Slow 3G; rapidly double-click or press Enter twice for lesson final answer, Money Save/Spent/Cash diary/Ask for extra, Send bear, mission Done, budget Finish, trade Propose, friend Send, greet, cosmetic Buy/Equip/None, Rename, Buddy Send/read aloud, PIN Unlock, and Parent Approve/Decline/Mark handled/Create goal/Assign task/Save rules/Update savings goal/Topup/Run-now/Inject-fault/Reset/settings toggles; all POST controls in that view disable until settlement, only one action request is sent, and errors re-enable controls.
- [ ] **C12 — Stable sheet focus:** Open My money, focus the amount or memo, type through at least two five-second polls and an SSE update; focus and the mobile keyboard remain in the field; Escape still closes using the latest callback. Review Child/Parent effects: none depend on an inline callback prop.
- [ ] **S6 — Parent lock:** Unlock parent, use Back to kid view, then Grown-ups; PIN is required and `sessionStorage.mq_parent` is absent. Repeat with the parent app-bar Lock button; PIN appears immediately and the token is cleared. Starting with a stored token in kid view must still require PIN on Grown-ups.
- [ ] **C6 — Immediate unauthorized handling:** Unlock parent, restart the API or invalidate its token, and immediately click Topup before the next poll; the failing action's 401 clears the token and opens PIN immediately. A wrong PIN still shows its friendly error and allows retry.
- [ ] **C9 — Repeated saves:** In My money choose $1 or $2 and save three times after each prior response; the amount stays in the field, the sheet stays open, and exactly three transfers occur. For Spend, verify the successful request does not clear the amount before the sheet closes.
- [ ] **C5 — Weekly budget state:** Finish a valid budget; after refresh Missions shows a checked, disabled Weekly budget challenge with no +50; reload preserves it. With an earlier server week in `lastBudgetWeek`, it becomes available again; do not derive this from the browser timezone.
- [ ] **Lesson replay copy:** Complete an already-passed lesson with a result containing `firstTime: false`; see “Nice review! No extra points for repeats.” without +20. Fail a final-answer request once, retry that answer, and verify the payload still has exactly one answer per question.
- [ ] **C4 — Parent form refresh:** Keep Goals or Allowance open in one parent tab and change the corresponding server values from a second authorized tab; after refresh the first form shows the new title/target or allowance/rules. Ordinary polls and next-payday changes must preserve typed values; a conflicting change to editable server values intentionally remounts only that form. A savings-goal edit must preserve the unsaved reward-goal/task drafts; unrelated security settings must preserve the allowance draft.
- [ ] **C7 — Empty savings goals:** Intercept the state responses to return `goals: []`; Child Home/Buddy and Parent Overview/Goals render “Set a savings goal” without errors. Home still opens My money, Buddy offers a goal suggestion, and Parent Goals shows blank title/default target fields.
- [ ] **C16 (also C15) — Navigation, reveal, connection copy:** Set `localStorage.mq_tab` to an unknown name and reload: Home renders. Leave a money/lesson sheet open until a trip returns: only the return reveal remains, and dismissing it never reopens the old sheet. At PIN, URL retains `?role=parent` and reload returns to PIN. Fail refresh: a loaded child/parent header shows Offline; a first visit without cached state shows “Can't reach MoneyQuest right now. Check your connection and try again.” with no port number.
- [ ] **C1 / C14 / C2 / C3 / C11 — Service worker and offline:** Clear site data, visit the production app once, wait for SW activation/art warming, then inspect cache `mq-v4` for `/`, every built hashed JS/CSS reference, manifest and all icons; registration starts without waiting for window load. Open Album offline (including a collected postcard not opened online), reload offline and inspect Home: saved JSON in `mq_last_state` renders, art is available, Offline pill/toast appears, and every mutation/voice request is disabled with zero POSTs. Reconnect: fresh state replaces the snapshot and actions re-enable. Return a 503 navigation or 404 static asset online: neither overwrites the good cache; offline navigation still opens the app. Consume a successful navigation response: cache write has no body-used error. `/api/*` never enters Cache Storage. On first install, controllerchange shows no update prompt. On an already controlled page, update the SW: controllerchange shows a persistent, clickable “Updated! Tap to reload” toast; tapping reloads.
- [ ] **C8 — Keyboard and label access:** Open a sheet from a focused button, Tab through all controls and Shift+Tab backwards: focus wraps inside; Escape/Close restores the opener. Focus a normal and secret map pin, press Space and Enter: each opens its sheet once and Space does not scroll the page. Clicking “How much?” focuses `#money-amount`; its label contains no div.
- [ ] **Map (AG2 #1, updated by F3) — Respect map interaction:** On a narrow screen, pan Maple’s travels with touch/drag or trackpad. It stays under user control; the surprise destination has no walker or automatic travel trail. Normal pin clicks still work.

- [ ] **F6 — Buddy off:** Parent turns Buddy off; tapping Maple shows “My grown-up switched chatting off for now.” and no bar. Switching off during a pending reply closes the bar and ignores the late reply.
- [ ] **F6 — Away:** Tapping the sign shows “Maple is on a trip! Back in 0:42”; countdown stays live, no talk bar opens, and zero chat requests are sent.
- [ ] **F6 — Offline:** Load the saved state offline; tapping Maple says “I can't chat while we're offline, but your postcards are right here!” and leaves the bar closed. Browse Album and open a cached postcard. Reconnect and chat again.
